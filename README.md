# سيزر جيم — الموقع

جيم متكامل في بني سويف الجديدة. موقع صفحة واحدة هدفه إن الزائر يشترك،
ولوحة تحكّم بتخلّي صاحب الجيم يعدّل الأسعار والعروض وأرقام التحويل وينشر
من غير ما يلمس كود.

## الملفات

| الملف | بيعمل إيه |
|---|---|
| `index.html` | الموقع كله — صفحة واحدة |
| `owner.html` | لوحة صاحب الجيم |
| `staff.html` | تفعيل العضويات وتسجيل حضور الحصص |
| `member.html` | مساحة العضو الجديدة: الرصيد، مدة الباقة، وسجل الزيارات مع نسخة استعراضية معلّمة بوضوح |
| `offers.html` | كروت العروض للسوشيال (تصدير PNG بمقاس 1080×1350) |
| `data/site.js` | **مصدر الحقيقة الوحيد**: الأسعار، العروض، المواعيد، التواصل |
| `data/img.js` | مقاسات الصور + نسخة مصغّرة ضبابية لكل صورة (متولّد آليًا) |
| `assets/core.css` | التوكنز والتايبوغرافي والحركة |
| `assets/site.css` | أقسام الموقع |
| `assets/site.js` | محرّك الموقع |
| `assets/hours.js` | منطق المواعيد لوحده (مفصول لأنه أهم جزء) |
| `assets/owner.*` | اللوحة |
| `assets/img/` | الصور بعد المعالجة |

## التشغيل محليًا — الواجهة والـ API

```bash
python -m pip install -r requirements-dev.txt
uvicorn server.app:app --reload --port 8000
```

بعدين افتح `http://localhost:8000`. SQLite متاح محليًا فقط؛ الإنتاج يرفض التشغيل به.

شغّل الاختبارات بـ:

```bash
python -m pytest -q
```

## الـ API وقاعدة البيانات

FastAPI بيخدم الواجهة الحالية والـ API من نفس الخدمة:

- `GET /api/health`
- `POST /api/orders` — لازم `Idempotency-Key`؛ السعر القادم من المتصفح بيتجاهل
- `GET /api/orders/{order_id}`
- `POST /api/payments/webhook` — توقيع HMAC SHA-256 في `X-Cezar-Signature`
- `GET /api/payments/return`
- `GET /api/admin/orders` — `Authorization: Bearer <ADMIN_TOKEN>`
- `POST /api/member/login` — رقم الموبايل ورمز العضو الخاص
- `GET /api/member/me` و`POST /api/member/logout` — جلسة عضو بملف Cookie آمن بدل حفظ الرمز في المتصفح
- `GET /api/admin/members` و`POST /api/admin/memberships` — إدارة العضويات
- `GET /api/admin/gym/status` و`POST /api/admin/gym/import-member` و`POST /api/admin/gym/retry/{id}` — ربط سيستم الجيم ومحاولات الإرسال
- `POST /api/admin/memberships/{id}/checkins` — تسجيل حضور حصة
- `POST /api/admin/attendance/{id}/void` — إلغاء حصة مسجلة بالخطأ

الجداول: `orders` و`webhook_events` و`admin_audit_logs`. الأمر
`python -m server.migrate` ينشئ المخطط بأمان، والخدمة تنشئ الجداول عند بدء التشغيل على Render.

### متابعة الاشتراك والحصص

افتح `staff.html` وأدخل `ADMIN_TOKEN` المحفوظ في Render. اختر طلب العميل أو أدخل بياناته
مباشرة، ثم راجع اسم الباقة وعدد الحصص وتاريخي البداية والنهاية قبل التفعيل. عند إنشاء
عضو جديد يظهر رمز دخول خاص مرة واحدة؛ سلّمه للعميل. يفتح العميل `member.html` ويدخل
رقم هاتفه والرمز ليشاهد المتبقي وسجل الحضور. الموظف يسجل الحصة عند دخول العميل،
ويمكنه إلغاء تسجيل خاطئ أو إصدار رمز جديد. الرموز لا تُحفظ كنص مكشوف في قاعدة البيانات.
الاشتراك لا يُفعّل تلقائيًا عند إرسال طلب أو إجراء دفع تجريبي؛ الإدارة تراجعه أولًا.

في التصميم الجديد، العضو يدخل مرة واحدة ثم يحصل على جلسة 8 ساعات بملف Cookie من نوع
`HttpOnly` و`SameSite=Strict`، و`Secure` في الإنتاج؛ رمز العضوية لا يُحفظ في
`sessionStorage`. بعد 5 محاولات فاشلة خلال 15 دقيقة يُوقف الدخول مؤقتًا. إصدار رمز
جديد يُلغي الجلسات القديمة. للاستعراض فقط افتح `member.html?preview=1`؛ تظهر بيانات
افتراضية بعلامة ظاهرة، ولا يُطلب أو يُعرض أي بيانات عضو حقيقي في هذه الحالة.

### تكامل سيستم الجيم

حاليًا `GYM_API_MODE=disabled` لأن اسم السيستم وتوثيق API ومفتاحه لم تُقدَّم بعد.
الكود يجهّز عقد HTTP واضحًا ومختبرًا بمحاكاة في الاختبارات، لكنه **ليس ربطًا حيًا**
بسيستم المكان. تفاصيل المسارات والحقول ومعالجة الأخطاء في
[`docs/GYM_API_CONTRACT.md`](docs/GYM_API_CONTRACT.md).

عند توفّر API متوافق، اضبط `GYM_API_MODE=http` و`GYM_API_BASE_URL` (HTTPS فقط)
و`GYM_API_KEY` على الخادم. لو API الفعلي مختلف، نعدّل طبقة `server/gym_api.py` فقط.
مفتاح الجيم لا يدخل HTML أو JavaScript. أعضاء السيستم الموجودون يُربطون من لوحة
الإدارة بعد مطابقة رقم الموبايل مع السيستم. عند تفعيل اشتراك جديد يُرسل بالمُعرّف
نفسه في `Idempotency-Key`؛ فشل الإرسال يظهر في اللوحة لإعادة المحاولة، من غير ادعاء
بأنه اتزامن. العضو المربوط يرى البيانات المباشرة من السيستم، أو نسخة محفوظة تحمل
تحذيرًا واضحًا عند انقطاعه؛ الحضور لا يُسجل محليًا له لمنع ازدواجية الحصص.

الجداول الإضافية: `members` و`memberships` و`attendance`. تُنشأ مع بداية تشغيل الخدمة.

## إعداد Render

الملف `render.yaml` ينشئ موارد منفصلة خاصة بسيزر فقط:

- Web Service: `cezar-gym-prod`
- PostgreSQL: `cezar-gym-db`
- Compute: Free للتجربة الأولية (السيرفر ينام عند الخمول وقاعدة البيانات تنتهي بعد 30 يومًا)
- Start command: `uvicorn server.app:app --host 0.0.0.0 --port $PORT`
- Health check: `/api/health`

المتغيرات موضحة في `.env.example`. `DATABASE_URL` مربوط بقاعدة Render، وRender يولّد
`ADMIN_TOKEN` و`PAYMENT_WEBHOOK_SECRET`. اضبط `PUBLIC_BASE_URL` على رابط Render أولًا،
ثم الدومين النهائي بعد ربطه. لا تضف أي سر إلى المستودع.

## الدومين

بعد شراء الدومين، أضفه في Render أولًا واتبع القيم التي يعرضها Render. الإعداد المعتاد:

- الجذر `@`: سجل `A` إلى `216.24.57.1` (أو CNAME flattening إلى اسم خدمة Render عند Cloudflare).
- `www`: سجل `CNAME` إلى اسم خدمة Render (`cezar-gym-prod.onrender.com` أو الاسم الفعلي الذي يظهر بعد الإنشاء).
- احذف أي سجل `AAAA` للجذر أو `www` أثناء الربط؛ Render يستخدم IPv4 للدومينات المخصصة.
- اجعل `PUBLIC_BASE_URL=https://your-domain.example` بعد نجاح التحقق.

Render يصدر HTTPS تلقائيًا بعد تحقق DNS. لا تحذف GitHub Pages قبل التأكد أن الدومين
والـ health check والصفحات الأساسية تعمل على البديل.

## الدفع

`PAYMENT_MODE` يقبل `mock` و`test` و`live`. حاليًا `mock` و`test` يستخدمان شاشة محاكاة
واضحة لا تستقبل أموالًا. وضع `live` مقفول عمدًا إلى أن يتم اعتماد حساب التاجر ومراجعة
عقد التوقيع والـ webhook الخاص بمزود الدفع. البنية الحالية تتحقق من التوقيع، الحدث المكرر،
الطلب، المبلغ، العملة والحالة قبل التحديث الذري. متغيرات Kashier محفوظة كأماكن إعداد فقط
ولا يتم إرسالها للمتصفح.

## بيانات تحتاج تأكيد المالك

- العروض الثلاثة انتهت في `2026-08-31`، لذلك الواجهة والخادم لا يطبقانها الآن رغم بقاء السجلات محفوظة.
- رقم Vodafone Cash ومعرّف/رابط InstaPay في `data/site.js` موصوفان أصلًا بأنهما مؤقتان؛ لم يتم افتراض صحتهما أو تغييرهما.
- أسماء بعض المدربين ما زالت placeholders حسب المصدر الحالي.

## التعديل

**الطريقة الطبيعية:** افتح `owner.html`، عدّل، واضغط **حفظ ونشر**.
اللوحة بتكتب `data/site.js` في المستودع عن طريق GitHub API، والموقع
بيتحدّث خلال دقيقة.

**يدوي:** عدّل `data/site.js` مباشرة. الأوبجكت لازم يفضل JSON صالح
ومن غير تعليقات جواه — اللوحة بتعيد كتابة الملف بالكامل وأي تعليق
جوه الأوبجكت هيتشال.

### الأسعار والخصم
`plans` فيها الأسعار **الأصلية**. الخصم بيتحسب في الموقع من `offers`
وبيتقرّب لأعلى لأقرب 5 جنيه. عرض عنده `minPeople` (عرض الصحاب) مش
بيغيّر الأسعار المعروضة — بيشتغل في الحاسبة بس.

### المواعيد
`schedule.segments` بالدقايق من نص الليل، مفهرسة برقم اليوم
(0 الأحد … 6 السبت). `to` أكبر من 1440 معناها إن الفترة بتكمّل لليوم
اللي بعده — ده اللي بيخلّي «الجيم شغّال لحد الفجر» تطلع صح.
المنطق كله في `assets/hours.js`.

## الصور

الصور الأصلية في `cezar-site-raw/` (بره المستودع). المعالجة بتشيل
لوجو الووترمارك بالقص — مش بمسح رقمي — وبعدين بتطلّع المقاسات اللي
الموقع محتاجها:

```bash
cd scripts && python build_images.py    # بيكتب assets/img/ + data/img.js
cd scripts && python build_logo.py      # الإمبلم بنسخه والأيقونات
```

**تغيير صورة:** استبدل الملف في `cezar-site-raw/` وشغّل السكربت تاني.

## الطلبات

كل طلب بيتسجل في قاعدة بيانات السيرفر قبل إظهار النجاح. طرق الكاش والتحويل اليدوي ما زالت
تفتح واتساب كقناة متابعة، لكن قاعدة البيانات هي مصدر الحقيقة. لوحة المالك تعرض طلبات
السيرفر بعد إدخال `ADMIN_TOKEN`، وتُبقي الطلبات اليدوية المحلية للتوافق فقط.

## الأمان

**أي حاجة في المستودع عامة.** الأسرار كلها متغيرات بيئة على Render ولا تُرسل للواجهة.
رمز إدارة الطلبات يُدخل وقت الاستخدام ويُحفظ في sessionStorage فقط.

التوكن لازم يكون **fine-grained** على المستودع ده بس، وصلاحيته
**Contents: Read and write** وبس، وعليه تاريخ انتهاء.
لما تخلّص اضغط **نسيان التوكن**.
